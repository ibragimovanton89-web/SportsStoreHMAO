# Почта покупателей

Транспорт `ICustomerEmailTransport` имеет реализацию `CustomerEmailTransport`: SMTP с обязательным STARTTLS либо локальный Capture только для Development. Используется обычный текст на русском, без HTML и полных реквизитов покупателя.

## Локальный запуск

В `appsettings.Development.json` настроен Capture для запуска из Visual Studio по адресу `https://localhost:44320`. Письма сохраняются в `C:\Users\ibrag\AppData\Local\SportsStoreHMAO\development-mail`; каталог создаётся при отправке первого письма. После изменения настроек перезапустите приложение и запросите письмо на `/customer/resend-confirmation`. На настоящую почту Capture ничего не отправляет. Для другого компьютера измените абсолютный путь, для другого порта — PublicOrigin.

В том же PowerShell, из которого запускается приложение:

```powershell
$env:Email__Mode = 'Capture'
$env:Email__PublicOrigin = 'https://localhost:7180'
$env:Email__CapturePath = Join-Path $env:LOCALAPPDATA 'SportsStoreHMAO\development-mail'
dotnet run --project src/SportsStore.Web --launch-profile https
```

Подставьте фактический HTTPS-порт своего launch profile. `CapturePath` должен быть абсолютным и находиться вне `wwwroot`; файлы не выдаются веб-сервером. Файлы содержат ссылки подтверждения/восстановления, поэтому доступны только разработчику и не должны попадать в Git, архив публичной статики или чужие журналы. Capture запрещён в Production, включая проверку при старте Web.

## SMTP

Задайте через защищённое окружение или secret manager:

| Ключ | Значение |
| --- | --- |
| `Email:Mode` | `Smtp` |
| `Email:PublicOrigin` | Собственный доверенный HTTPS origin без пути/query/credentials |
| `Email:From` | Подтверждённый у провайдера адрес отправителя |
| `Email:Smtp:Host` | Сервер провайдера |
| `Email:Smtp:Port` | Обычно 587, STARTTLS |
| `Email:Smtp:User` | Учётная запись SMTP |
| `Email:Smtp:Password` | Секрет SMTP, отсутствующий в исходниках |

Текущий транспорт использует `SmtpClient.EnableSsl`: STARTTLS, а не implicit TLS порта 465. Сертификат SMTP проверяется стандартными средствами платформы. Реальный SMTP провайдера не заменяется тестовым захватом: его подключение, SPF/DKIM/DMARC и доставку владелец проверяет отдельно перед запуском. Пустая конфигурация не отправляет письма; регистрационный ответ остаётся нейтральным, но подтверждение почты требует работающего транспорта.

Ссылки строятся только из `Email:PublicOrigin`. Недоверенный Host HTTP-запроса не используется. Для Development допустим явно заданный loopback HTTP origin, однако защищённая cookie покупателя требует HTTPS для браузерных сценариев.

## Одноразовые ссылки

Покупательский CustomerTokenProvider использует стандартный механизм Identity и отдельный срок один час; провайдер приглашений сотрудников не изменён. Токен кодируется Base64Url и привязан к пользователю, назначению и security stamp. ResetPassword обновляет stamp, что делает использованный reset-токен и старые сессии недействительными. Восстановление не подтверждает почту. GET ссылки подтверждения показывает форму; изменение выполняет POST, чтобы сканер почтовых ссылок не расходовал её автоматически.

Открытые коды не хранятся в общей очереди. Регистрация сначала фиксирует пользователя/покупателя и только затем генерирует письмо. При сбое можно повторно запросить письмо; нейтральный ответ не раскрывает существование адреса. Токены не включаются в бизнес-аудит и тексты ошибок. Ключи Data Protection необходимо сохранять и защищать: иначе перезапуск обесценит ссылки и cookie.

## Очередь решений по опту

`NotificationOutbox` ссылается только на `WholesaleDecision`; в ней нет подтверждающих токенов, адресов и реквизитов. Решение и outbox фиксируются одновременно. `NotificationWorker` раз в 15 секунд обрабатывает до 20 писем. `FOR UPDATE SKIP LOCKED` даёт одному обработчику двухминутную аренду, SMTP выполняется после коммита. Неуспешные попытки повторяются с задержками 2, 4, 8, 16 минут, максимум пять начатых попыток.

Письмо имеет устойчивый `X-SportsStore-Message-Id`. Доставка имеет семантику **at least once**: сбой после принятия письма SMTP и до записи SentAt может привести к повторному письму. Бизнес-решение при этом не повторяется. Исчерпавшая попытки запись остаётся для диагностики; оператор после устранения причины может отдельно запланировать повтор в БД. В LastErrorCode хранится только безопасный код, без SMTP-ответа и адреса.

Письмо сообщает о конкретном историческом решении; текущие условия всегда определяются в кабинете из Customer. При отсутствии подтверждённого адреса попытка завершается безопасной ошибкой. Внешняя отправка во время автоматических проверок не используется.

Официальные механизмы: [подтверждение и восстановление Identity](https://learn.microsoft.com/en-us/aspnet/core/blazor/security/account-confirmation-and-password-recovery?view=aspnetcore-10.0), [перепроверка состояния Blazor](https://learn.microsoft.com/en-us/aspnet/core/blazor/security/?view=aspnetcore-10.0).

## Уведомления покупательских заказов

Используется отдельная `OrderNotification`, связанная с уникальным `OrderEvent`. Существующая очередь оптовых решений с DecisionId не изменена. Запись очереди атомарна с бизнес-событием; отправка только после commit. Процессор использует SKIP LOCKED, аренду на две минуты, максимум пять попыток и отложенный повтор. Ошибки сохраняются кодом DeliveryFailed без адресов/токенов. Сбой транспорта не отменяет заказ и не создаёт его заново.

Письмо содержит номер, сумму товаров, статус и срок, с локальной ссылкой из проверенного Email:PublicOrigin. Нет обещания оплаты/отгрузки. Capture применяется в изолированных тестах с адресами example.invalid. Реальную SMTP-доставку необходимо настроить отдельно. При сбое после фактической отправки до отметки SentAt возможна повторная доставка письма (at-least-once), но не повтор заказа.
