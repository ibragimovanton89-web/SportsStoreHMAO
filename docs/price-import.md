# Импорт BallMarket

## Проверенный источник
Фактический путь исходного файла: C:\Users\ibrag\Downloads\Price-list_BallMarket.ru.xls.
SHA-256: D0E0B9B1A49EA69ACB1397DC298D566C32859120FD912B34E82D04882DA16C59.
Бинарный OLE/BIFF XLS; один лист «Лист 1»; дата «На 28.07.26», RUB.
Независимое чтение xlrd и C# ExcelDataReader подтвердило 4 694 содержательных/внутренних строк, 4 405 уникальных товаров и 559 пустых остатков. ExcelDataReader дополнительно выдавал последнюю пустую строку из BIFF; общая нормализация отбрасывает пустые строки в конце, сохраняя исходные номера остальных.

Парсер BallMarketParser реализует ISupplierPriceParser. Он отделён от IPriceImportService; для другого поставщика добавляется другой адаптер/выбор parser в DI, каталог менять не нужно. Консольный preview на этом этапе явно маршрутизирует только ballmarket. Тот же сервис может вызывать будущая задача расписания; скачивание и расписание сейчас отсутствуют.

## Поля
Таблица ищется по семи заголовкам среди первых 200 строк; в этом документе это строка 36. Внешний код берётся из столбца перед названием.

| Столбец | Содержание | Хранение |
|---|---|---|
| B | Внешний код без заголовка | SupplierOffer.ExternalCode, строка с ведущими нулями |
| C | Наименование | SourceName, собственное Product.Name не затрагивается |
| D | Ед. | SupplierUnit: шт/пар/компл/упак |
| E | Кол. в кор. | UnitsPerBox; не MOQ и не кратность |
| F | Мелкий Опт | small, цена за единицу D |
| G | Опт | wholesale, цена за единицу D |
| H | Крупный Опт | large, цена за единицу D |
| I | Остаток | nullable Stock, не собственный склад |

00024387: ADIDAS JD8036, шт, 12 в коробке, 4633/4455/4325 RUB, остаток 8.
Пустой остаток → NULL/Unknown, числовой 0 → известный ноль. Пустая цена → отсутствует; прежняя действующая цена сохраняется. Неверная/отрицательная/нулевая закупочная цена → диагностика и блокировка партии. Отрицательные количества также запрещены.

Разделы сохраняются как исходный текст, последовательные заголовки объединяются через « / ». Никакой автоматической регистрации бренда по такому тексту нет. BABOLAT, NEVA, TECNIFIBRE остаётся разделом. Неуверенные характеристики не заполняют собственный каталог: сохраняются исходное название/раздел и JSON с NeedsReview и маркерами НОВИНКА/СЦ*. Для артикула, размера, цвета и материала требуется ручная проверка текста. Ни маркеры, ни цвет ячейки не создают акции.

Исходные значения ячеек сохраняются в ImportRow.RawJson; нормализованная запись — ParsedJson. Числовой код с Excel-форматом из ведущих нулей форматируется по нему. Если исходный числовой код уже утратил нули и формат их не задаёт, парсер не придумывает длину кода.

Порог small=150000, wholesale=450000, large=2000000 — условия **закупки у поставщика**, извлечённые из шапки. Они не дают клиенту магазина права на опт. Текст накопительной скидки хранится как исходные условия; формула не реализована.

## Команды
Сначала настройте соединение и миграции по README. Все команды выполняются в корне решения:
```powershell
dotnet run --project src/SportsStore.Tools -- parse "C:\Users\ibrag\Downloads\Price-list_BallMarket.ru.xls"
dotnet run --project src/SportsStore.Tools -- preview "C:\Users\ibrag\Downloads\Price-list_BallMarket.ru.xls"
dotnet run --project src/SportsStore.Tools -- report <batchId>
dotnet run --project src/SportsStore.Tools -- apply <batchId>
dotnet run --project src/SportsStore.Tools -- inspect
```
Подставьте UUID из JSON-отчёта. parse работает без БД. preview сохраняет только Supplier при первом знакомстве, ImportBatch/ImportRow. Предложения, текущие закупочные цены и каталог он не меняет. При первом apply исходного файла ожидается 4405 предложений и 13215 текущих закупочных цен; первичная история фиксирует начальные значения с OldAmount=NULL.

Для следующего файла повторите preview → report → apply. Исчезнувшие коды остаются с прежним LastSeenAt; товары и собственный склад не удаляются и не обнуляются. Время LastSeenAt обновляется только при применении нового документа. Повторно применённый batch и идентичный SHA ничего не меняют.

## Просмотр предложений и служебные команды цен
```powershell
dotnet run --project src/SportsStore.Tools -- offers 00024387
dotnet run --project src/SportsStore.Tools -- pricing-source <variantId> <offerId>
dotnet run --project src/SportsStore.Tools -- rule Retail <yourMarkupPercent> 1 default
dotnet run --project src/SportsStore.Tools -- rule Wholesale <yourMarkupPercent> <minSkuQuantity> variant <variantId>
dotnet run --project src/SportsStore.Tools -- propose <offerId>
dotnet run --project src/SportsStore.Tools -- proposals
dotnet run --project src/SportsStore.Tools -- price-apply <proposalId>
dotnet run --project src/SportsStore.Tools -- manual <variantId> Retail 1 <yourFixedPrice>
```
Числа вводятся с точкой. Значения в угловых скобках — параметры, не готовые команды/рекомендации наценки. tariff — сознательное подтверждение закупочного уровня оператором. Коэффициент означает число магазинных единиц в одной единице поставщика, не число изделий в коробке. Количество коробки не подтверждает коэффициент.

demo создаёт только вымышленные данные с префиксом DEMO, Draft-карточкой, учебной закупкой 100 RUB и правилами 30/20/10% только для DEMO-варианта. Нет опубликованных цен и нет изменения глобального минимального заказа. Пользователи demo-Pending/demo-Approved не имеют паролей. Не используйте demo-условия для реального прайса.

## Транзакции, повтор и ошибки
- Preview/apply и автоматическое создание карточки одного поставщика сериализуются PostgreSQL advisory transaction lock.
- Apply повторно читает статус под блокировкой; повтор одного batch — успешная операция без изменений.
- Preview хранит Supplier.Revision; чужое применение прайса или создание карточки делает его устаревшим. Команда repreview <batchId> заново сравнивает сохранённые строки с текущими предложениями и обновляет отчёт, не создавая дубликат партии.
- Более старая дата не применяется, даже после repreview. Новая корректировка с той же датой допустима после актуального preview.
- Ошибочная строка или конфликтующий дубль блокирует всю партию. Идентичный дубль игнорируется с диагностикой.
- Вся запись предложений, цен, истории, статуса и предложений пересчёта происходит в одной транзакции. Ошибка ограничений откатывает её полностью.
- Смена единицы поставщика снимает подтверждение перевода; смена порога выбранного тарифа снимает подтверждение тарифа.
- Собственный каталог, ручные цены и остатки поставщику не принадлежат и импортом не перезаписываются.
- Устаревшее предложение пересчёта не применяется: нужно снова propose. Конкурентный Serializable-конфликт требует повторного прочтения оператором, скрытого перезаписывания нет.

## Безопасность и библиотека
[ExcelDataReader 3.9.0](https://www.nuget.org/packages/ExcelDataReader/3.9.0), MIT, поддержка бинарного XLS и .NET Standard, совместимого с .NET 10. Excel COM и установленный Excel не нужны.
Формулы не вычисляются: читаются только сохранённые значения. Макросы, hyperlinks и содержимое ячеек не запускаются. Файл читается локально, никуда не загружается. Лимиты: 10 MiB, 1 лист, 20000 строк, 64 колонки, 8000 символов в ячейке, 16000 в шапке. Утилита локальная для доверенного оператора; будущий HTTP-upload потребует отдельной авторизации и защиты от злоупотреблений.



## После импорта: выборочная закупка

Импортированная таблица теперь служит источником раздела [«Мои заказы»](purchasing.md). Ручные минимальные суммы поставщика (`ManualMinimumAmount`), созданные закупки, их ценовые снимки и собственные остатки импорт не изменяет. Карточки создаются выборочно из собственных закупок или фактически принятого товара. Сохранённая цена от процента конкретной закупки защищена так же, как ручная фиксированная цена.
