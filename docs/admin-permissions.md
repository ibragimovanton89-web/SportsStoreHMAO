# Полномочия сотрудников

Policies `Staff` и `Administrator` проверяют текущие данные Identity в PostgreSQL: подтверждение аккаунта, отсутствие блокировки, security stamp, признак выполненной MFA и роль. Cookie и скрытые кнопки сами по себе не дают полномочий. Каждая административная команда и чтение повторяют серверную проверку.

| Действие | Admin | Manager | Customer / гость |
|---|---|---|---|
| Обзор, предложения поставщика, цены, покупатели | Да | Да | Нет |
| Загрузка и preview XLS, отчёт и повторная проверка | Да | Да | Нет |
| Применение прайса | Да | Нет | Нет |
| Создание черновика и варианта, фотографии черновика | Да | Да | Нет |
| Изменение опубликованной/архивной карточки | Да | Нет | Нет |
| Создание категории/бренда | Да | Да | Нет |
| Изменение/удаление существующего справочника | Да | Нет | Нет |
| Сопоставление и выбор источника цены | Да | Только черновики | Нет |
| Подготовка пересчёта | Да | Только без публикации | Нет |
| Тариф, наценка, ручная цена, применение расчёта, общие настройки | Да | Нет | Нет |
| Публикация, архивирование, возврат в черновик | Да | Нет | Нет |
| Изменение клиента, подтверждение/отзыв опта | Да | Нет | Нет |
| Приглашения, роли, блокировка сотрудников, аудит | Да | Нет | Нет |

`AutoApplyProposals` не расширяет права Manager: административный сервис передаёт запрет автоматического применения в существующий расчёт. Preview не меняет действующие закупочные предложения. Применение импорта разрешено только Admin.

Фоновая перепроверка Blazor выполняется каждые 15 секунд. Команды проверяют права немедленно при выполнении, независимо от видимости старой вкладки. Изменение роли и блокировка меняют security stamp. Нельзя заблокировать или лишить роли последнего активного Admin. Роли сотрудников независимы от сегмента и подтверждения опта покупателя.

Локальная CLI использует отдельный доверенный адаптер, отсутствующий в Web. Доступ к компьютеру и конфигурации CLI является административным доступом: не предоставляйте консоль оператора покупателям.


## Закупки и витрина

| Действие | Admin | Manager | Гость / Customer |
|---|---|---|---|
| Просмотр закупок и собственного склада | Да | Да | Нет |
| Подбор и редактирование до передачи | Все заказы | Свои | Нет |
| Ручные пороги трёх тарифов | Да | Нет | Нет |
| Передача, в пути, приёмка, отмена, возврат на редактирование | Да | Нет | Нет |
| Карточка из выбранной закупки | Да | Черновики | Нет |
| Цена от закупки или ручная цена | Да | Нет | Нет |
| Опубликованная витрина и её изображения | Да | Да | Да |

Фотографии черновиков/архива выдаются только после текущей проверки Staff. Ответы изображений имеют `Cache-Control: no-store`, чтобы публикация не оставляла долгоживущий кеш после скрытия карточки. Публичные DTO не содержат закупочных цен, порогов, сессий или реквизитов.

Удаление закупки без приёмок разрешено только Admin, для статусов Draft/Created/Cancelled. Manager не может вызвать удаление напрямую. Старая версия формы отклоняется; повтор успешно выполненной команды с тем же идентификатором не меняет данные повторно. Приёмка и удаление сериализованы одной блокировкой.
